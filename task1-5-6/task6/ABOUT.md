## Задание 6. CDN

### Новые компоненты

| Сервис | Описание |
|--------|----------|
| CDN Edge Servers (PoP) | Кеширующие серверы в разных регионах (EU, US, Asia, RU) для быстрой доставки статики |
| Origin Server | Хранилище статических файлов (images, CSS, JS) — источник для CDN |

### Принцип работы

#### Статический контент (images, CSS, JS)
1. Браузер запрашивает `https://cdn.example.com/image.png`
2. Запрос попадает на ближайший **CDN Edge Server** (по геолокации)
3. Если файл в кеше — CDN отдаёт его напрямую (cache hit)
4. Если нет — CDN запрашивает у **Origin Server**, кеширует и отдаёт (cache miss)

#### Динамические запросы (API)
1. JavaScript в браузере делает `fetch('https://api.example.com/users')`
2. Запрос идёт напрямую на **API Gateway** (минуя CDN)
3. API Gateway выбирает один из доступных инстансов (список из Consul)
4. API Instance обрабатывает запрос (Redis кеш + MongoDB)

#### Service Discovery (Consul)
1. API инстансы при запуске регистрируются в Consul
2. Consul отслеживает health-check всех инстансов
3. API Gateway запрашивает у Consul список здоровых инстансов
4. При добавлении/удалении инстанса Consul автоматически обновляет реестр
5. API Gateway узнаёт об изменениях и корректирует балансировку

### Преимущества CDN

| Преимущество | Описание |
|--------------|----------|
| Снижение latency | Статика раздаётся с ближайшего к пользователю сервера |
| Разгрузка Origin | Большинство запросов обслуживается кешем CDN |
| Отказоустойчивость | При падении одного PoP трафик перенаправляется на другой |
| Масштабируемость | CDN автоматически справляется с пиками нагрузки (Black Friday) |
